# 通达信日线技术条件版事件研究：数据接入设计

## 目的与范围

将用户本地通达信 `.day` 日线接入已冻结的 B1 事件研究器，先检验信号的技术条件是否具有统计优势。该版本覆盖沪深主板代码 `600/601/603/605/000/001/002`，不因当前缺少历史市值和 ST 状态而伪造或替代这些字段。

原始数据根目录为 `C:\Users\playd\Desktop\A_Share_Backtesting\data\tdx_raw`。2026-07-14 的只读核验显示，其中有 12,280 个 `.day` 文件；目标主板文件为 3,439 个，日线记录为 32 字节定长格式，样例数据覆盖至 2026-07-13。

## 方案选择

采用“全市场技术条件版”。它保留代码池、KDJ、DIF、缩量、BBI/B1 信号、次日开盘执行、非重叠事件和随机对照；市值门槛和非 ST 过滤均明确禁用。

不采用当前市值、当前 ST 名称或静态近似值替代历史字段，因为它们会带来未来信息或幸存者偏差。后续取得逐日市值与 ST 数据后，应以同一日期和代码左连接并重新运行；结果应另标为“完整公式版”，不得与本版混称。

## 数据流与接口

新增本地导入命令，输入为 `.day` 根目录，输出为一个 UTF-8-SIG 标准日线 CSV 和一个数据质量 JSON：

```text
tdx_raw/{sh,sz}/lday/*.day
  -> 解析 date, code, open, high, low, close, volume
  -> 按主板前缀过滤并排除指数、ETF、可转债等非股票代码
  -> 输出 daily_bars_technical.csv
  -> event_study_run.py 使用 technical-only 配置运行
  -> 生成现有七类研究产物与限制说明
```

导入结果仍满足既有日线契约，以便复用现有信号与事件研究代码：

- `name`：使用代码本身，仅作可读标签，不能用于 ST 判断；
- `market_cap`：填 `0`，同时配置 `min_market_cap=0`；
- `is_st`：填 `false`，同时输出元数据声明“ST 状态不可用，未筛除”；
- `is_suspended`：填 `false`，不根据成交量推断停牌；现有事件层只在实际缺失、无效开盘价或明确涨跌停字段存在时标记未成交。

`.day` 价格以文件中的整数价格除以 100 后写出。首轮采用未复权价格：信号、入场、退出和回撤均使用同一口径，避免将当前时点生成的前复权序列混入历史决策。分红、配股和除权造成的持有期跳空属于此版本的已知限制。

## 配置与可追溯性

新增一个技术条件版配置文件，除下列差异外与冻结的默认事件研究配置保持一致：

```json
{
  "min_market_cap": 0,
  "data_scope_label": "technical_only_no_historical_market_cap_or_st",
  "price_adjustment": "unadjusted"
}
```

运行报告必须显示：原始数据根目录、导入时间、代码数、日期范围、剔除的非目标代码数、价格口径、缺失字段、冻结配置哈希（或完整配置文本）以及“不能代表完整原公式”的提示。

## 错误处理与边界

- 遇到非 32 字节整数倍的 `.day` 文件，导入失败并列出路径；不静默截断。
- 遇到无法解析的交易日、非正价格或同一代码日期重复，导入失败并列出原因。
- 无历史市值/ST 数据时，导入器不允许用户设置正市值门槛或声明已执行 ST 过滤。
- 北交所、科创板、创业板、指数、基金、债券文件被记录在质量报告中，但不会进入本版回测样本。
- 本次实测只使用截至 `analysis_end` 的数据；指标预热需要在开始日前至少保留 120 个交易日。

## 验证与验收

测试先于导入实现，至少覆盖：一条 32 字节记录的字段/价格缩放、目标主板筛选、非 32 字节文件拒绝、输出元数据的限制标识，以及技术条件配置拒绝正市值门槛。

真实数据运行后，验收要求为：

1. 所有目标主板文件均被统计为已导入或显式失败；
2. 标准日线 CSV 能通过既有数据契约；
3. 事件研究完整产出信号审计、事件明细、日期组合、汇总、随机对照与报告；
4. 审计确认每个已成交事件满足 `signal_date < entry_date < exit_date`，未成交事件无收益；
5. 报告中的结论标题和限制说明均为“技术条件版”，不宣称验证了市值/ST 筛选。

## 非目标

本次不补抓远程数据、不推断历史 ST/市值、不模拟盘中止损或分批建仓，也不把事件研究结果外推为实盘策略收益。
